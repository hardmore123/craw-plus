# 海外爬取项目全量重组方案

## 当前问题

1. **文件散落** — 代码在`海外数据爬取_部署包/overseas/`，skill在`海外/.kiro/skills/`，数据在`data/`，文档在`docs/`，分散在两个顶层目录
2. **DB备份堆积** — 部署包根目录有40+个`overseas.db.bak_*`文件(各111MB)，占4GB+
3. **data目录混乱** — 中英文目录名混用(加拿大/墨西哥/秘鲁 + ca/mx/sa/eu/jp)
4. **schema重复** — `overseas/sites/*/schema.json` + `schemas/declarative/*.schema.json` + `docs/specs/*.spec.json` 三处
5. **无统一入口** — 新人无法快速理解"从哪开始、怎么跑"

## 重组原则

1. **不破坏可运行性** — `overseas/`包的import路径不变，只移动skill/data/docs
2. **DB分区域** — 主库`overseas.db`保持，按区域导出子库供独立运行
3. **sites按区域分子目录** — 260站从平铺改为`japan/na/sa/eu/asia`5个子目录
4. **DB备份清理** — 40+个`overseas.db.bak_*`移到`backup/`或删除
5. **skill保持活文档** — skill不移动位置(已在`海外/.kiro/skills/`)，只建索引链接

## 执行步骤

1. 创建目标目录结构
2. 移动overseas/sites/ → 按区域分子目录
3. 导出区域DB(从主库按site_id过滤)
4. 移动文档 → 文档/
5. 清理DB备份 → backup/
6. 生成README.md总索引
7. 验证import路径不断

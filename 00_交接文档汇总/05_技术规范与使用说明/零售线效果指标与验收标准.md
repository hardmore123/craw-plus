## 第一部分：效果指标

指标分四层。**L1 是红线（不达标即不可交付）**，其中零售线的红线与 SPEC 线不同：
SPEC 线红线是"找全率"，零售线红线是"**匹配准确率**"。

### L1 — 数据正确性（红线，一票否决）

| 指标 | 定义 | 阈值 | 采集方式 |
|---|---|---|---|
| **型号匹配准确率** ★ | 人工抽检 N 个已匹配商品，型号确实一致的比例 | **= 100%**（抽检 20 个零错） | 人工抽检，对比商品页标题/型号与目标型号 |
| **误匹配率** ★ | 把配件/无关商品当成目标型号的比例 | **= 0** | 同上；出现即判失败 |
| **价格填充率** | 有价格的商品 / 已匹配且在售的商品 | ≥ 95% | 导出表统计（缺货商品不计入分母） |
| **币种正确率** | 币种标注与站点实际一致 | = 100% | 抽检，重点查裸 `$` 站点（MXN/USD 歧义） |
| **评价去重率** | 重复入库的评价条数 / 总条数 | **= 0** | 按 `(product_id, review_key)` 查库重 |
| **评价字段非空率** | 评分/标题/正文三者至少两项非空的比例 | ≥ 90% | 导出表统计 |
| **尺寸解析正确率** | 尺寸列与型号实际尺寸一致 | ≥ 98% | 抽检 |

> **匹配准确率必须是 100%，不是 95%。** 一条错匹配会污染该型号的整条价格时序
> 与评价集合，且极难被下游发现。宁可 `skip`（少一条）也不能错一条。

### L2 — 覆盖面

| 指标 | 定义 | 目标 | 当前 |
|---|---|---|---|
| **自动化站点数** | 无需写代码即可跑通价格+网评的零售站 | 阶段目标 8 站 | **0**（现有均为人工写 schema/adapter） |
| **国家数** | 已覆盖的国家 | 4（日/墨/加/美） | 1（日本，且为硬编码） |
| **声明式占比** | 走 RetailSpec 的站 / 全部零售站 | ≥ 70% | 约 60% 有 schema.json，但均人工编写 |
| **型号覆盖率** | 在该站找到页面的型号 / 型号清单总数 | ≥ 85%（未匹配如实 skip） | 需按站测量 |

> **型号覆盖率不是越高越好**。若为提高它把 `on_no_match` 改成 `first`，
> 会直接击穿 L1 红线。覆盖率低说明该站确实没上架，是事实而非缺陷。

### L3 — 效率收益

| 指标 | 定义 | 目标 | 基线（日本线现状） |
|---|---|---|---|
| **接站耗时** | 从给 URL 到 RetailSpec 达标 | ≤ 3 小时 | kakaku 脚本约 1250 行，数天 |
| **接站代码量** | 新站需写的 Python 行数 | **0 行**（纯配置） | 数百至千行 |
| **日常重跑 LLM 成本** | 每次采集的 token | **0** | 0（已达成） |
| **增量省请求率** | 增量模式请求数 / 全量请求数 | ≤ 30% | `s4_reviews` 已实现，未量化 |

### L4 — 系统健康度

| 指标 | 目标 | 当前 |
|---|---|---|
| RetailSpec 持久化（库表 + 版本） | 100% | 0%（未设计表） |
| 改版检出时延（retail-health） | ≤ 7 天 | 不可测（未实现） |
| 站点白名单准入（合规） | 100% | 0% |
| 失败现场留档 | 100% | 部分 |

## 第二部分：任务表与验收标准

### 0. 通用验收规则

**三条硬门槛**（任何任务声明完成前必须全过）：

| 门槛 | 验证 | 判据 |
|---|---|---|
| 代码可编译 | `py -3.12 -m py_compile <改动文件>` | exit 0 |
| 回归不破坏 | 见下方回归基线 | 日本线数字不变 |
| 文档已同步 | 人工核对 | 改白名单必须同步 RetailSpec 规范 §12 |

**回归基线**（改动零售公共代码后必跑）：

| 线 | 期望 |
|---|---|
| kakaku 网评 | 与改动前同一型号集合的评价条数一致 |
| kakaku 价格 | 8 个日本店铺列仍正确产出（店铺列动态化后尤其要验证） |
| SPEC 线 | Philips CA 仍 11 系列 25 型号（确认没碰坏共享代码） |

**禁止事项**（出现即验收不通过）：
- 把 `match.on_no_match` 设成 `first` 来提高覆盖率
- 放宽匹配准确率阈值
- 为凑价格填充率把缺货商品也算进分母
- 用"标题+作者"拼 `review_key`

否则是合规风险敞口。

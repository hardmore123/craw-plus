# 海外爬取项目数据库说明文档

> 生成：2026-09-24　基准：`data/overseas.db` + `data/mx/overseas_mx.db`
> 表结构定义源文件：`overseas/schema.sql`

---

## 一、总览

本项目用 **两个 SQLite 库** 分别存放不同区域的数据，按国家线物理隔离，避免跨区域污染、便于单独备份与部署。

| 库 | 路径 | 大小 | 区域 | 表数 | 最后更新 |
|---|---|---|---|---|---|
| **主库** | `data/overseas.db` | 20.6 MB | 日本 + 北美（加/美）+ 欧洲 | 20 | 2026-09-23 |
| **墨西哥库** | `data/mx/overseas_mx.db` | 3.0 MB | 墨西哥 | 20 | 2026-09-21 |

两库**表结构完全相同**（同一份 `schema.sql`），只是数据内容不同。

> ⚠️ 南美线（秘鲁/厄瓜多尔/哥伦比亚/智利/玻利维亚/阿根廷/巴拿马/危地马拉）的数据**不在上述两库中**，而是以 CSV 交付文件形式存放（`data/南美欧洲价格全量_最终交付.csv` 等），未落 SQLite 库。

---

## 二、为什么分两个库

| 原因 | 说明 |
|---|---|
| **地理隔离** | 墨西哥的零售站（amazon_mx / liverpool_mx / coppel_mx 等）与北美/日本完全独立，分库避免误操作 |
| **备份独立** | 长时全量抓取前必须先备份；墨西哥库小（3 MB），备份快 |
| **并发安全** | 两个库可以被不同进程同时操作而不互相锁死 |
| **部署灵活** | 墨西哥线可单独部署到墨西哥节点，无需带主库 |

## 四、表关系（ER 概要）

```
site (1) ──< product (N) ──< price_snapshot (N)
                      └──< price_shop_snapshot (N)
                      └──< review (N)
                      └──< review_summary (N)  [1:1 per product]
                      └──< product_spec (N)

crawl_run (1) ──< crawl_error (N)
            └──< retail_task_status (N)
            └──< kakaku_task_status (N)
            └──< spec_series_status (N)

spec_series (1) ──< spec_row (N)
              └──< spec_series_status (N)

spec_entry_audit  (独立，记录入口审计，不与 spec_series 关联)
spec_untranslated (独立，记录待翻译项)
kakaku_thread_state (独立，评价帖断点)
```

**核心关联**：`product.site_id → site.id`，所有价格/评价/规格都挂在 `product` 上。

| first_seen / last_seen | TEXT | 首次/末次抓到时间 |

### 5.3 `price_snapshot` — 价格快照

| 字段 | 类型 | 说明 |
|---|---|---|

| price | REAL | 现价 |
| list_price | REAL | 原价（划线价） |
| currency | TEXT | 货币（CAD / USD / JPY / MXN） |
| in_stock | INTEGER | 是否有货（0/1） |
| raw_text | TEXT | 价格原始文本（解析前） |
| captured_at | TEXT | 抓取时间 |

### 5.4 `review` — 用户评价

| 字段 | 类型 | 说明 |
|---|---|---|
| product_id | INTEGER | → product.id |
| review_key | TEXT | 评价唯一键（Amazon 用 R 开头 14 位 ID；kakaku 用帖子+楼层） |
| rating | TEXT | 星级（1-5） |
| title / body | TEXT | 标题 / 内容 |
| author | TEXT | 评论人 |
| review_date | TEXT | 评论日期 |
| verified | INTEGER | 是否 Vine/已购买 |
| helpful_count | INTEGER | 有用数 |
| review_url | TEXT | 评价链接 |
| image_urls | TEXT | 图片地址（JSON 数组） |
| image_count | INTEGER | 图片数 |
| video_urls | TEXT | 视频地址 |
| has_video | INTEGER | 是否含视频 |
| captured_at | TEXT | 抓取时间 |

### 5.5 `spec_series` / `spec_row` — 规格采集

**spec_series**：每个品牌官网的每个系列一行。

| 字段 | 说明 |
|---|---|
| brand | 品牌 code（如 `hisense_ca`） |
| brand_name | 展示名 |
| series | 系列名 |
| url | SPEC 页 URL |
| models | 型号数（JSON 或逗号分隔） |
| first_seen / last_seen | 首次/末次抓到时间 |

**spec_row**：宽表格式，一行 = 一个规格项，一列 = 一个型号。

| 字段 | 说明 |
|---|---|
| series_id | → spec_series.id |
| category | 区分（如「画質」「音声」） |
| item_ja | 日文项目名 |
| item_zh | 中文项目名（翻译后） |
| row_order | 行序 |
| values_json | 各型号的值（JSON 数组，与 spec_series.models 对应） |
| captured_week | 抓取周（如 202609） |

### 5.6 `retail_task_status` — 零售站每型号终态

| 字段 | 说明 |
|---|---|
| run_id | → crawl_run.id |
| region | 区域 |
| site_code | 站点代码 |
| brand / brand_name | 品牌 |
| model | 型号 |
| item_id | 站内 SKU |
| product_id | → product.id（有则已入库） |
| status | **终态**：ok / no_item / no_price / no_reviews / failed / blocked / summary_only |
| size | 尺寸 |
| price | 价格（有则填） |
| currency | 货币 |
| row_count / new_count | 本轮行数 / 新增数 |
| captured_at | 抓取时间 |

> **终态语义**（铁律 #6）：
> - `ok` = 价格或网评已成功入库
> - `no_item` = 站上确实没有该型号（搜索页无结果）
> - `no_price` = 有商品页但无价格（缺价 > 错价，留空不造假）
> - `no_reviews` = 有商品但无评价（站点未启用评价组件）
> - `failed` = 搜索页没渲染/被拦/出口 IP 不对（≠ no_item）
> - `blocked` = 被反爬拦截（需代理/住宅 IP）
>
> 失败型号（failed/no_item/no_price/no_reviews/blocked）直接跳，**不无限重试**。

### 5.7 `spec_entry_audit` — 入口审计（找全率闸门）

| 字段 | 说明 |
|---|---|
| brand | 品牌 code |
| expected_series_count | 人工核对：官网应有多少系列 |
| discovered_series_count | 引擎实际发现多少系列 |
| expected_model_count | 人工核对：应有多少型号 |
| discovered_model_count | 引擎实际发现多少型号 |
| termination_reason | 终止原因（stable / no_growth / page_set_stable / coveo_total_count 等） |

> 这是 skill 铁律 #9 的落地点：`expected_*` 必须去官网数一遍，不填 = 关掉找全率闸门。

## 九、操作注意事项

| 事项 | 说明 |
|---|---|
| **并发写回滚** | 两个任务同时写同一库会互相覆盖备份；串行跑或分库（教训：欧洲 Amazon 数据被并发 MX 任务回滚） |
| **integrity_check** | 交付前跑 `PRAGMA integrity_check` 应返回 `ok` |
| **VACUUM** | 大量 DELETE 后跑 `VACUUM` 回收空间 |
| **不要手改 product/review** | 价格污染修复只动 `retail_task_status` 的 price 列 + `rebuild_amazon_csvs.py`，不直接改 product/review |
| **缺价 > 错价** | 宁留空不造假价；污染修复：先备份受影响行 → DELETE → rebuild |
| **schema 迁移** | `overseas/cli.py init-db` 自动补齐缺失列（如 `product.size`、`review` 的媒体列） |

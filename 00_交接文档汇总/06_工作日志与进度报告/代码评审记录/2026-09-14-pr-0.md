# 美国官网 SPEC 分页、响应捕获与型号边界审查

本次检查了 `海外/overseas` 当前的 TCL、Hisense、Sony、LG 美国 SPEC 适配器，以及 `BrowserFetcher`/`open_dom` 的响应捕获链路。需要先说明的是，`海外` 目录没有 `.git`，因此不存在可验证的相对 `HEAD` diff；唯一可用的 `crawl4ai-main` Git 根目录的 diff 是证书核对 Web 部署变更，与本次品牌抓取代码无关。响应捕获参数追加在 `BrowserFetcher.page` 末尾，现有调用没有被破坏，但品牌发现逻辑仍有明确的漏抓和错纳入路径。**Watch for:** **confirmed** TCL 的 `*-series` 产品会在分页前被 TV 过滤器丢掉，Sony 的 K/XR 型号会生成错误系列码，LG 会把 `/lifestyle-products/` 当成 TV；**likely** LG 的 `totalCount=91` 目前只是审计值而不是完整性门槛，且响应截断后的回退正则可能重新扫入 `childResults`。

**Verdict**: NEEDS_CHANGES

## High-level view

TCL 的分页依赖普通 `page` 链接且入口过滤器与自身支持的 `qm8k-series` slug 冲突，分页可能在发现阶段就得到空集；12 页上限也没有完整性审计。Hisense 已将分页和 Load more 接到同一入口流程，并跨页按型号去重，但没有防止安全阈值触发后静默截断的总数校验。

Sony 的 KD 分支会去掉尺寸前的 `KD`，但同一规则没有去掉文档示例中的 `K` 或 `XR` 前缀，因此系列分组名称会偏移；分页同样依赖固定 12 页和“无新增即停止”。

LG 的捕获链路会在导航前监听 Coveo 响应，并在合法 JSON 中只遍历顶层 `results`，所以正常 JSON 不会把 `childResults` 变体放大；但路径白名单同时允许 TV 与 Lifestyle Screen，且 `totalCount=91` 没有驱动分页、重试或失败判定，完整性仍未得到保证。

## Issues (7)

1. **[confirmed] TCL `*-series` 入口漏抓** — `_TV_HINT` 没有覆盖 `_SERIES_FROM_SLUG` 明确支持的 `*-series` slug，像 `qm8k-series` 会被过滤为空；将 TV 判定改为基于集合/产品结构或加入可靠的系列型号规则，并增加 fixture 回归。
2. **[confirmed] Sony K/XR 系列码错误** — `_parse_model` 只对 `KD` 去前缀，`k65xr90m2` 变成 `KXR90M2`、`xr65a95l` 变成 `XRA95L`；统一 K/KD/XR 型号规则并用实际型号断言系列名。
3. **[confirmed] LG Lifestyle Screen 进入 TV 集合** — DOM、Coveo 顶层结果和回退正则都接受 `/us/lifestyle-products/`，尺寸型 Lifestyle Screen 会被当成 TV 型号；TV SPEC 应限制为 `/us/tvs/`，或明确按内容类型排除。
4. **[likely] LG 的 91 总数没有完整性门槛** — `totalCount` 只写入 `last_entry_audit`，没有比较顶层 `results`/去重型号数，也没有请求后续页或在少于 91 时失败；应补齐响应分页或至少将数量不一致标记为 partial/failed。
5. **[likely] 响应截断回退可能放大 `childResults`** — 6 MB 限制或非 JSON 响应会触发对整个正文的 URL 正则，而不是只读顶层 `results`；应避免在截断/JSON 解析失败时把正文当完整发现结果，改为记录捕获不完整并重试或只接受完整 JSON。
6. **[likely] TCL/Sony/Hisense 固定上限会静默漏抓** — 三个适配器分别最多遍历 12 页，Hisense 每页最多点 12 次 Load more，且 TCL 还假定一个系列只有一个产品页；应跟随 next/total 或写入 expected/discovered mismatch，超过阈值时失败而不是当作完整入口。
7. **[confirmed] 美国线缺少专门回归测试** — 当前目录没有针对四个适配器的 pytest/unittest 或离线 HTML/JSON fixture；补充分页、K/KD/XR、顶层/childResults、Lifestyle 和响应截断测试，避免这些边界再次回归。

### TCL 集合分页与系列发现

**confirmed：`*-series` slug 在分页前被过滤。** `overseas/overseas/sites/tcl_us/adapter.py:27` 的 `_TV_HINT` 只允许 `-tv`、`qled`、`mini-led` 等关键词，而同文件 `:32-33` 的 `_SERIES_FROM_SLUG` 明确按 `.../products/<series>-series` 提取系列。`_collect_products()` 在 `:58-78` 先执行 `if not any(x in low for x in _TV_HINT): continue`，所以文档自己的 `qm8k-series` 示例不会进入 `products`；无网络最小样本 `TclUsAdapter._collect_products(None, '<a href="/products/qm8k-series">')` 已返回空列表。`series_entries()` 的 `:143-151` 后续再怎么分页也无法发现这些系列，这是当前最直接的 TCL 漏抓阻塞。

分页在站点使用普通 `page` 锚点且总页数不超过 12 时会取当前页之后最小的页码（`:90-111`），并用 `seen_products`、`seen_series`（`:120-151`）抑制重复产品/系列，因此未看到必然的重复输出。**likely：** `ENTRY_MAX_PAGES=12`（`:49-50`）是硬上限，且 `_next_page_url()` 只识别 `<a href>` 的 `page=`，没有总数或“已完整遍历”审计；超过上限或站点用按钮分页时会把部分集合当完整集合。另一个条件性风险是 `:147-149` 每系列只保留第一个产品页；这只在站点不满足“一个产品页包含该系列全部尺寸”的前提时漏型号。

`parse_tcl_us_html()` 在 `overseas/overseas/spec_parser_us.py:98-145` 按型号标题切段并横向合并，依赖固定 class 顺序和 `- <MODEL>` 标题格式；当前没有离线 HTML fixture 证明实际页面改版时仍能产出所有型号，这一覆盖缺口归入测试问题而不是另一个独立阻塞。

### Hisense 分页与 Load more

入口调用 `overseas/overseas/sites/hisense_us/adapter.py:95-117` 使用 `?page=N` 遍历最多 12 页；`spec_entry_click_selectors`、`spec_entry_click_repeats` 和增长选择器在 `:52-56` 声明。`open_dom()` 在入口页把这些配置传给 `BrowserFetcher.page()`（`overseas/overseas/scenarios.py:85-111`），浏览器层 `overseas/overseas/fetchers.py:567-635` 对按钮做可见/禁用检查、点击、等待，并在产品链接数量不再增长时停止；跨页的 `seen_models`（adapter `:98-114`）抑制了分页和 Load more 结果中的重复型号。

这条链路在每页 Load more 次数有限、站点 `page` 参数确实代表下一页时符合目标。**likely：** `ENTRY_MAX_PAGES=12` 与每页 `spec_entry_click_repeats=12` 都是静默安全阀，`page_urls` 没有新型号时立即结束（`:115-117`），没有 expected/discovered 数量校验；如果按钮点击失败、页面参数被忽略或当前库存超过上限，结果会是部分成功而不是可识别的 partial。修复前至少应把点击/分页终止原因和发现数写入审计，并在数量不一致时阻止“完整”导出。

Hisense 产品页点击 `Full Specs` 后优先读取 ProductSpecification，失败时回退到标题/描述概要（`:145-168`）。这是代码注释明确的产品限制：无头页面可能无法填充完整 Wix 规格，因此当前可以接受“完整规格可得时取完整、否则概要”的降级；导出方不能把概要表误标为完整官网规格。

### Sony KD/K/XR 型号归组与分页

**confirmed：KD 之外的前缀归一化不符合文件自身目标。** `_MODEL_RE` 在 `overseas/overseas/sites/sony_us/adapter.py:24-25` 接受 `kd|xr|k`，但 `_parse_model()` 的 `:49-57` 只有 `prefix.lower() == 'kd'` 时取 `tail`，否则拼接 `prefix + tail`。因此无网络最小样本得到：`k65xr90m2 -> (65, 'KXR90M2', ...)`、`kd65x85k -> (65, 'X85K', ...)`、`xr65a95l -> (65, 'XRA95L', ...)`；这与同文件文档 `:4-6` 对 `k65xr90m2` 所写的系列 `XR90M2` 不一致。它会污染系列名，并在同一系列同时出现 K/XR 表示时拆成多个系列；KD 路径本身是正确的，应保留并补齐 K/XR 的测试。

分页循环 `:79-99` 固定构造 `currentPage=1..12`，遇到空页或 `added == 0` 即停止。**likely：** 这要求 Sony 接口使用 1-based `currentPage`、页数不超过 12、且参数变化必然产生新链接；代码没有读取 next/total、没有记录期望型号数，也没有在重复页后尝试备用分页方式。当前无法用目标仓库的测试或 HEAD diff 证明实际接口满足这些前提，因此全量行为不能判定为已覆盖。

### LG Coveo 顶层结果、childResults 与 TV 范围

**confirmed：合法 JSON 的顶层提取方向是对的。** `overseas/overseas/sites/lg_us/adapter.py:71-93` 先 `json.loads()`，只取 payload 的顶层 `results`，再逐个读取 `raw.ec_uri_link`/`clickUri`/`uri`；不会递归进入 `childResults`。`_collect()` 在 `:94-126` 还会按型号去重，因此 DOM、HTML 和同一响应的重复链接不会直接形成重复型号。

**confirmed：Lifestyle Screen 没有被排除。** 同文件 `:23-27` 的 DOM/正文正则、`:100-103` 的选择器、`:58-62` 的型号提取和 `:89-92` 的响应路径判断都同时接受 `/us/tvs/` 与 `/us/lifestyle-products/`。`_parse_model()` 在 `:63-70` 只检查 2–3 位尺寸和字母尾码，`27lx6tyga` 这样的 Lifestyle Screen 会通过 24–120 的范围检查（`:115-123`）。因此只要 Coveo 顶层 91 个结果里含那两个 Lifestyle Screen，它们就会作为 LG TV 的型号进入系列分组；这是代码确定存在的纳入路径，不是重复去重能解决的问题。

**likely：`totalCount=91` 目前不能证明发现了 91 个型号。** `series_entries()` 在 `:130-157` 从每个捕获正文读取 `totalCount` 并写入 `expected_model_count`，但只调用一次 `open_dom()`，不按 `totalCount` 发起分页，也不比较 `expected_count` 与去重后的 `discovered_model_count`。如果 Coveo 响应的 `results` 只是第一页，审计会显示期望 91 而采集仍照常返回部分 entries；应将不一致变成明确失败/partial，或实现 Coveo 分页。

**likely：无效/截断响应会重新引入 childResults。** `_response_product_paths()` 在 JSON 解析失败或没有顶层 `results` 时于 `:74-79` 对整个 body 执行 `_RESPONSE_PRODUCT_RE`；而 `BrowserFetcher.page()` 在 `overseas/overseas/fetchers.py:638-648` 会先按 `capture_response_limit=6_000_000` 截断正文。截断后的合法 JSON 变成不可解析文本时，嵌套 `childResults` 中的 URL 也会被正则找出。正常且小于限制的 JSON 不会触发此问题；响应捕获层应把“正文不完整/解析失败”作为不完整信号，而不是继续将正文当作可信产品全集。

### BrowserFetcher/open_dom 参数兼容性

**confirmed：** `FetchResult.response_bodies` 和 `meta` 位于 dataclass 末尾（`overseas/overseas/fetchers.py:52-55`），`BrowserFetcher.page()` 的两个新参数也追加在现有参数之后（`:435-452`），旧的按位置传参不会因参数顺序改变而错位。响应监听在 `goto()` 前注册（`:479-490`），只有适配器声明入口响应模式时才收集正文。

`open_dom()` 没有把响应参数插入旧的公开位置，而是在入口页识别后从适配器属性读取，再以关键字传给 `page()`（`overseas/overseas/scenarios.py:58-64,85-111,126-142`）。现有仓库调用继续使用原有关键字/上下文管理器形态，LG 通过 `spec_entry_response_pattern` 和 `spec_entry_response_limit`（adapter `:45-50`）启用捕获；没有发现会破坏现有生产调用的路径。

### 测试覆盖与可接受限制

目标目录没有美国四品牌专门的 pytest/unittest 或 fixture；现有 `_probe_spec.py` 等是运行探针，不包含这些边界的断言。已执行的无网络最小 smoke test 验证了 TCL `qm8k-series` 被过滤为空、Sony K/KD/XR 解析结果以及 LG 顶层 JSON/`childResults`/Lifestyle 行为；没有执行真实官网请求，因此不能把 12 页上限、Sony `currentPage` 语义或 Coveo `results` 实际长度视为已验证。

可以接受的限制是：Hisense Full Specs 获取失败时回退概要规格；TCL/Sony/Hisense 的固定安全阀在已知库存明确低于阈值且审计标记为完整时可作为运行保护。不能接受的是把阈值触发、91 与发现数不一致、响应解析失败或 Lifestyle 纳入继续当作成功快照写出。

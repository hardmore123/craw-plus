# 海外采集框架交付说明 v0.3.0

## 1. 交付内容

本交付包包含一个可扩展的海外电商采集框架，以及日本电视官网 SPEC 采集线。框架支持价格、评价、通用规格入库；SPEC 线按品牌采集官网规格，按 ISO 周保存快照，并按品牌导出横向 Excel。

当前已完成并验证的日本品牌：

| 品牌 code | 官网 | 系列 | 型号 | Excel 行数 | 中文覆盖 |
|---|---|---:|---:|---:|---:|
| `hisense_jp` | Hisense 日本 | 13 | 44 | 101 | 100% |
| `sony_jp` | Sony BRAVIA 日本 | 9 | 38 | 104 | 100% |
| `regza_jp` | REGZA 日本 | 39 | 139 | 564 | 100% |
| `panasonic_jp` | Panasonic VIERA 日本 | 8 | 25 | 52 | 100% |
| `tcl_jp` | TCL 日本 | 28 | 78 | 283 | 100% |
| `sharp_jp` | Sharp AQUOS 日本 | 13 | 44 | 56 | 100% |

六个结果文件已在开发环境重新导出：`SPEC_海信日本.xlsx`、`SPEC_索尼日本.xlsx`、`SPEC_REGZA日本.xlsx`、`SPEC_松下日本.xlsx`、`SPEC_TCL日本.xlsx`、`SPEC_夏普日本.xlsx`。代码包本身不包含运行数据库、缓存和这些结果文件；重新运行刷新脚本即可生成。

## 3. 安装和前置条件

- Python >= 3.10；开发机 Windows 复现使用：
  `C:\Users\likunyuan\AppData\Local\Programs\Python\Python312\python.exe`。
- 六个日本官网适配器均使用 Playwright 浏览器路径；Windows 可使用 Edge channel，Linux 服务器需要可执行的离线 Chrome，并设置 `OVERSEAS_BROWSER_EXECUTABLE`。
- Excel 导出需要 `openpyxl==3.1.5`；浏览器抓取需要 Playwright Python 包。
- 服务器必须能访问目标官网；代理通过 `OVERSEAS_PROXY` 配置。请遵守目标站点条款和内部合规要求。

从源码目录安装：

```bash
python -m pip install -r requirements.txt
# 或安装可选依赖：
python -m pip install -e ".[browser,xlsx]"
```

安装后可用 `python -m overseas.cli sites --json` 确认六个 `*_jp` 站点均已注册。`pyproject.toml` 已显式包含六个日本站点包，避免安装后自动发现缺包。

## 4. 手工采集和导出

数据库默认路径是 `data/overseas.db`，也可以通过全局 `--db` 或 `OVERSEAS_DB_PATH` 指定。单品牌流程：

```powershell
$py = 'C:\Users\likunyuan\AppData\Local\Programs\Python\Python312\python.exe'
$db = 'data\overseas.db'
& $py -m overseas.cli --db $db init-db
& $py -m overseas.cli --db $db spec-crawl --site sharp_jp
& $py -m overseas.cli --db $db spec-export --site sharp_jp --format xlsx --out SPEC_夏普日本.xlsx
$env:PYTHONIOENCODING = 'utf-8'
& $py check_xlsx.py SPEC_夏普日本.xlsx
```

把 `sharp_jp` 和输出文件替换为其它品牌即可。`REGZA`、`TCL` 页面较重，建议设置 `$env:OVERSEAS_NAV_TIMEOUT='60'`。`spec-crawl` 写入当前 ISO 周快照；同一周重复执行是幂等更新。词典更新后可只执行 `spec-export`，无需重新采集。

## 5. 六品牌周度刷新

统一入口会按固定顺序执行：

1. 对每个品牌执行 `spec-crawl`；
2. 导出到项目根目录固定的 `SPEC_*.xlsx` 文件；
3. 检查表头、型号列、规格行和中文覆盖率；
4. 任一品牌失败或出现未翻译项目时返回非零，便于定时任务告警。

Windows 手工执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\refresh_spec.ps1
```

参数示例：

```powershell
# 只刷新一个品牌
powershell -ExecutionPolicy Bypass -File .\scripts\refresh_spec.ps1 -Site sharp_jp
# 只根据数据库重导出，不访问官网
powershell -ExecutionPolicy Bypass -File .\scripts\refresh_spec.ps1 -ExportOnly
# 直接调用跨平台脚本
& $py scripts\refresh_spec.py --db data\overseas.db --output-dir .
```

脚本参数：`--site` 可重复、`--db`、`--output-dir`、`--export-only`、`--allow-incomplete`、`--fail-fast`。默认未翻译项目视为失败，不建议生产任务使用 `--allow-incomplete`。

## 6. Linux 定时任务

复制代码和 `deploy/` 后，先按《部署说明.md》完成 venv、离线 Chrome、环境变量和网络自检，再安装 SPEC 单元：

```bash
cd /home/hisense/pro/overseas
sudo cp deploy/overseas-spec.service /etc/systemd/system/
sudo cp deploy/overseas-spec.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start overseas-spec.service
sudo journalctl -u overseas-spec -n 100 --no-pager
sudo systemctl enable --now overseas-spec.timer
systemctl list-timers overseas-spec --no-pager
```

`overseas-spec.timer` 默认每周日 03:20 执行，错过后补跑并增加随机延迟；服务超时上限 3 小时。它与原有 `overseas-monitor.timer` 分离，SPEC 失败不会改变 Amazon 监控任务的职责。

## 7. Windows Task Scheduler

建议以实际运行采集的 Windows 用户注册，而不是以没有浏览器配置的系统账户注册：

```powershell
$root = 'C:\Users\likunyuan\Desktop\爬取项目\海外'
$action = New-ScheduledTaskAction -Execute 'PowerShell.exe' -Argument ('-NoProfile -ExecutionPolicy Bypass -File "{0}"' -f (Join-Path $root 'scripts\refresh_spec.ps1'))
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Sunday -At 3:20am
Register-ScheduledTask -TaskName 'Overseas-SPEC-Weekly' -Action $action -Trigger $trigger -Description '六个日本电视品牌 SPEC 周度刷新' -Force
```

注册后先手工测试：

```powershell
Start-ScheduledTask -TaskName 'Overseas-SPEC-Weekly'
Get-ScheduledTaskInfo -TaskName 'Overseas-SPEC-Weekly'
```

任务失败时查看历史记录或直接运行 PowerShell 文件；脚本返回非零表示至少一个品牌采集、导出或校验失败。

## 8. 交付包和排除项

在项目根目录运行：

```powershell

```

## 10. 已知限制

- 松下当前官网动态渲染的 W80C/MR770 型号页未稳定出现在系列列表，已采集的主力系列不受影响；后续可单独补抓。
- TCL 旧系列部分规格 JSON 端点已返回 404，框架会跳过并记录，不强行填充空规格。
- 规格页面改版、网络超时或代理失效可能导致周度任务非零退出；应查看 `crawl_run`、`crawl_error` 和定时任务日志后再重跑。
- 定时刷新是批处理，不是常驻服务；浏览器、代理、目标站点合规确认均由部署环境负责。


## 11. SPEC 型号汇总清单

为便于后续在 Amazon、零售平台或评价平台按型号搜索，交付包中的 `scripts/` 目录还包含：

```text
scripts/export_spec_models.py
```

该脚本从 `data/overseas.db` 的 `spec_series.models` 读取六品牌当前已发现的规格号，默认按品牌和标准化型号去重，输出一行一个品牌-型号的 CSV/XLSX/JSON 清单，同时保留原始型号、所属系列、SPEC 来源 URL、最近快照周、搜索词和重复审计字段。

```powershell
$py = 'C:\Users\likunyuan\AppData\Local\Programs\Python\Python312\python.exe'
$stamp = Get-Date -Format 'yyyyMMdd'
& $py scripts\export_spec_models.py --format all --out "data\SPEC_型号汇总_$stamp"
```

当前开发数据库验证结果：110 个系列、370 个原始型号槽位、368 个品牌内唯一型号；海信 44、索尼 38、REGZA 139、松下 25、TCL 78、夏普 44。`--include-duplicates` 可保留原始重复槽位。该脚本输出的是当前数据库已保存的型号，不等同于已经下架的历史型号全集，因为现有数据库尚未建立逐型号周快照表。


## 12. SPEC 系列状态审计与导出

本版本新增系列级状态历史表 `spec_series_status`（schema 版本 2），解决“抓取为空或失败但型号表没有行”时无法追踪的问题。每次 SPEC 运行按 `run_id + brand + series` 保存一条最终结果：

- `success`：成功访问并解析出至少一个型号和一行规格；
- `empty`：请求成功但没有可用 table、型号、JSON 或规格行；
- `failed`：404、其它 HTTP 错误、超时、浏览器/网络异常、解析异常；多型号系列只要部分应抓型号失败也标为 `failed`，但保留成功部分和计数。

状态记录同时保留请求/实际/尝试 URL、系列 ID、期望/成功/空/失败型号数、规格行数、错误类型、消息和时间。底层 `crawl_error` 继续记录 URL/入口错误。入口 `list_series` 或 `series_entries` 为空时写入 `stage=entry,kind=empty`，并将该次 `crawl_run` 标记为 `failed`。

交付包中的新增脚本：

```text
scripts/export_spec_status.py
```

导出命令：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd'
& $py scripts\export_spec_status.py `
    --db data\overseas.db `
    --format all `
    --out "data\SPEC_系列状态_$stamp"
```

`--format all` 生成 CSV/XLSX/JSON；`--site` 可重复。该清单与 `scripts/export_spec_models.py` 分离，空/失败系列只出现在状态清单中，不生成空型号伪行。`refresh_spec.py` 已在每轮刷新后自动生成状态文件，即使 Excel 校验失败也会尝试输出，供定时任务告警和补采使用。

旧数据库兼容：没有 `spec_series_status` 历史的有效 `spec_series` 会在导出时标为 `status=success,status_source=legacy`；不会伪造过去的 empty/failed。交付验收除六个 Excel 外，还必须检查状态文件的状态计数、URL、型号/规格计数和 `crawl_run/crawl_error`。

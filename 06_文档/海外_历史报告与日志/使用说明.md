# 海外采集框架使用说明

版本：v0.3.0  
适用范围：海外电商采集框架、日本六品牌电视 SPEC 采集线  
文档状态：与 `工作日志.md`、`部署说明.md`、`交付说明.md` 同步维护

## 1. 使用前先看这里

本项目有两类采集任务：

1. **电商采集**：Amazon 等站点的搜索、商品详情、价格、评价和通用规格；
2. **日本电视 SPEC 采集**：海信、索尼、REGZA、松下、TCL、夏普官网的电视规格表。

如果你的目标是日本电视规格，优先使用：

```text
scripts/refresh_spec.py
```

不要手工把六个品牌命令写进不同的定时脚本。Windows PowerShell 和 Linux systemd 都调用同一个编排器，这样输出文件名、数据库路径、中文覆盖率校验和失败退出规则保持一致。

## 4. 六品牌 SPEC 日常采集

### 4.1 品牌与入口

| code | 品牌 | 官网入口 | 当前基线 |
|---|---|---|---|
| `hisense_jp` | 海信日本 | `https://www.hisense.co.jp/tv/` | 13 系列、44 型号、101 行 |
| `sony_jp` | 索尼日本 | `https://www.sony.jp/bravia/lineup/` | 9 系列、38 型号、104 行 |
| `regza_jp` | REGZA | `https://www.regza.com/tv/lineup` | 39 系列、139 型号、564 行 |
| `panasonic_jp` | 松下 VIERA | `https://panasonic.jp/viera/products.html` | 8 系列、25 型号、52 行 |
| `tcl_jp` | TCL 日本 | `https://www.tcl.com/jp/ja/tvs` | 28 系列、78 型号、283 行 |
| `sharp_jp` | 夏普 AQUOS | `https://www.sharp.co.jp/aquos/lineup/` | 13 系列、44 型号、56 行 |

当前数据库六品牌最新快照均为 `2026-W37`，六个导出文件中文覆盖均为 100%。后续官网型号数量会随官网上下架变化，不能把基线数量当成永久固定值；刷新时应记录本周数量变化。

### 4.2 采集一个品牌

以夏普为例：

```powershell
$env:OVERSEAS_NAV_TIMEOUT = '60'
& $py -m overseas.cli --db data\overseas.db spec-crawl --site sharp_jp
```

导出：

```powershell
& $py -m overseas.cli --db data\overseas.db spec-export `
    --site sharp_jp `
    --format xlsx `
    --out SPEC_夏普日本.xlsx
```

校验：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
& $py check_xlsx.py SPEC_夏普日本.xlsx
```

`check_xlsx.py` 会打印：

- sheet 名；
- 总列数和数据行数；
- 前三列是否为 `区分/项目/项目（中文）`；
- 型号列；
- 中文覆盖率；
- 前 20 个未翻译项目；
- 前 15 行样例。

PowerShell 默认控制台可能使用 GBK，打印日文时请先设置 `PYTHONIOENCODING=utf-8`。

### 4.3 只采指定系列

调试页面或补采某个系列时，`--series` 可以重复：

```powershell
& $py -m overseas.cli --db data\overseas.db spec-crawl `
    --site sharp_jp `
    --series X7A
```

注意：只采指定系列后，再导出该品牌时，数据库中其它系列的最新数据仍可能被一起汇总；如果是正式周度刷新，不要使用 `--series`。

### 4.4 六品牌统一刷新

完整刷新：

```powershell
& $py scripts\refresh_spec.py
```

或使用 Windows 入口：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\refresh_spec.ps1
```

脚本会：

1. 按海信、索尼、REGZA、松下、TCL、夏普顺序执行 `spec-crawl`；
2. 每个品牌成功后导出固定文件名；
3. 检查 Excel 文件存在且非空；
4. 检查前三列表头；
5. 检查型号列和规格行存在；
6. 检查中文覆盖率；
7. 任一品牌失败时继续其它品牌，最后返回退出码 1。

常用参数：

```powershell
# 只刷新夏普
& $py scripts\refresh_spec.py --site sharp_jp

# 同时刷新多个指定品牌
& $py scripts\refresh_spec.py --site regza_jp --site sharp_jp

# 指定数据库和输出目录
& $py scripts\refresh_spec.py `
    --db data\overseas.db `
    --output-dir .\weekly-output

# 只从已有数据库快照重导出，不访问官网
& $py scripts\refresh_spec.py --export-only

# 页面变更后暂时允许未翻译项目，但不建议周度生产任务使用
& $py scripts\refresh_spec.py --allow-incomplete

# 首个品牌失败立即停止
& $py scripts\refresh_spec.py --fail-fast
```

### 4.5 词典更新后只重导出

先查看未命中项目：

```powershell
& $py -m overseas.cli --db data\overseas.db spec-dict
```

编辑：

```text
overseas/dict/spec_ja_zh.json
```

然后执行：

```powershell
& $py scripts\refresh_spec.py --export-only
```

词典变化不需要重新请求官网，因为导出层会对数据库中空的中文项目调用当前词典。只有以下情况必须重新采集：

- 官网新增了规格项目；
- 官网改变了表格结构、JSON 字段或型号列表；
- 原采集周没有该系列；
- 之前页面因超时/阻断导致数据库没有有效行。

### 4.6 SPEC 上市时间行（用于上市时间筛选）

海信等官网 SPEC 规格页本身不含「発売日/上市时间」，因此 SPEC 采集不产生上市时间。为支持**按上市时间筛选机型**，SPEC 导出可在表格**顶部插入一行「上市时间」**（区分=上市时间、项目=発売日、中文=上市时间），每个机型列填其发售日。

上市时间来源为 価格.com 商品页発売日，先抓一份「型号→上市时间」映射：

```powershell
# 轻量抓取（只走 搜索→商品页，不抓评价），输出 data\发售日_<brand>.json
& $py scripts\crawl_kakaku_release.py --brand hisense_jp
```

之后正常导出即可自动带上上市时间行（`spec-export` 默认读取 `data\发售日_<brand>.json`）：

```powershell
& $py -m overseas.cli --db data\overseas.db spec-export `
    --site hisense_jp --format xlsx --out SPEC_海信日本.xlsx
# 若映射文件在别处：--release-map path\to\发售日_hisense_jp.json
```

说明：

- 发售日变动不频繁，无需每周重抓；映射文件存在时 `refresh_spec.py` 也会自动带上上市时间行；
- 型号按归一化（去空格/短横、大写）匹配，`RGB 100UXS` 等写法也能对上；
- kakaku 无独立商品页的型号（如海信 `75A6S`、`55A6S`、`32S6S`）该列留空；
- 该行项目/中文均非空，不影响 `refresh_spec.py` 的中文覆盖率校验。

## 5. 数据库和周快照使用

查看数据库统计：

```powershell
& $py -m overseas.cli --db data\overseas.db stats
```

查看所有站点注册信息：

```powershell
& $py -m overseas.cli sites --json
```

查看最近运行记录和失败：

```powershell
& $py -c "import sqlite3; c=sqlite3.connect('data/overseas.db'); print(*c.execute('SELECT id,scenario,site,status,ok_count,fail_count,started_at,message FROM crawl_run ORDER BY id DESC LIMIT 20'), sep='\n'); c.close()"
```

查看 SPEC 快照周和系列：

```powershell
& $py -c "import sqlite3; c=sqlite3.connect('data/overseas.db'); print(*c.execute('SELECT brand,COUNT(*),MAX(last_seen) FROM spec_series GROUP BY brand'), sep='\n'); print(*c.execute('SELECT captured_week,COUNT(*) FROM spec_row GROUP BY captured_week ORDER BY captured_week DESC'), sep='\n'); c.close()"
```

建议每周刷新前先备份数据库：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
New-Item -ItemType Directory -Force data\backup | Out-Null
Copy-Item data\overseas.db "data\backup\overseas_before_$stamp.db"
```

数据库备份很重要：同一周重复刷新通常是幂等更新，但如果适配器逻辑有误，仍可能把错误值写入当前周快照。备份可以在确认异常后恢复。

## 7. Windows Task Scheduler 周度任务

注册任务：

```powershell
$root = 'C:\Users\likunyuan\Desktop\爬取项目\海外'
$action = New-ScheduledTaskAction `
    -Execute 'PowerShell.exe' `
    -Argument ('-NoProfile -ExecutionPolicy Bypass -File "{0}"' -f (Join-Path $root 'scripts\refresh_spec.ps1'))
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Sunday -At 3:20am
Register-ScheduledTask `
    -TaskName 'Overseas-SPEC-Weekly' `
    -Action $action `
    -Trigger $trigger `
    -Description '六个日本电视品牌 SPEC 周度刷新' `
    -Force
```

测试：

```powershell
Start-ScheduledTask -TaskName 'Overseas-SPEC-Weekly'
Start-Sleep -Seconds 10
Get-ScheduledTaskInfo -TaskName 'Overseas-SPEC-Weekly'
```

查看/停用/删除：

```powershell
Get-ScheduledTask -TaskName 'Overseas-SPEC-Weekly'
Disable-ScheduledTask -TaskName 'Overseas-SPEC-Weekly'
Unregister-ScheduledTask -TaskName 'Overseas-SPEC-Weekly' -Confirm:$false
```

任务建议以实际开发用户运行。若以 SYSTEM 账户运行，Edge 用户目录、代理设置和项目文件权限可能不同。

## 8. 故障排查

### 8.1 `sites` 中缺少品牌

```powershell
& $py -m overseas.cli sites --json
```

若缺少 `sharp_jp` 等：

1. 确认当前目录是项目根目录；
2. 确认 `overseas/sites/<brand>/adapter.py` 和 `__init__.py` 存在；
3. 运行 `python -m py_compile overseas\sites\<brand>\adapter.py`；
4. 查看 CLI 的加载警告；
5. 若是安装后的 venv，检查 `pyproject.toml` 是否包含该 package。

### 8.2 浏览器启动失败

Windows：

- 确认使用指定 Python 3.12；
- 确认 Playwright 已安装；
- 关闭占用浏览器 profile 的残留进程后重试；
- 用 `python -m overseas.cli config` 查看浏览器 channel 和超时。

Linux：

- 确认 `OVERSEAS_BROWSER_EXECUTABLE` 指向真实 Chrome 可执行文件；
- 执行 `ls -l` 检查权限；
- 确认 `chrome` 和 `chrome_crashpad_handler` 可执行；
- 缺系统库时执行 `python -m playwright install-deps chromium`；
- systemd 下检查 `HOME`、`LANG`、`LC_ALL` 和 `overseas.env` 权限。

### 8.3 页面超时或无法连接

先调高导航超时：

```powershell
$env:OVERSEAS_NAV_TIMEOUT = '90'
```

再检查代理和域名连通性。不要先降低抓取间隔；目标站点可能因为频率过高触发阻断。Linux 可执行：

```bash
timeout 12 bash -c '</dev/tcp/www.sharp.co.jp/443'
timeout 12 bash -c '</dev/tcp/www.regza.com/443'
```

### 8.4 采集成功但 Excel 行数/型号数下降

可能原因：

- 官网下架了系列或型号；
- 入口页改版，系列链接选择器失效；
- 旧型号 JSON/HTML 返回 404；
- 页面在等待时间内没有完成 JS 渲染；
- 代理或浏览器被目标站点阻断。

处理顺序：

1. 先保存当前数据库和 Excel；
2. 用 `--site` 只重跑问题品牌；
3. 用 `--series` 定位问题系列；
4. 查看 `crawl_run`、`crawl_error`；
5. 必要时用浏览器手工打开入口和 SPEC URL；
6. 确认是官网 404 后，记录为官网下架，不要手工填空规格；
7. 确认是解析器问题后再修改对应 adapter/parser。

### 8.5 中文覆盖率下降

```powershell
& $py -m overseas.cli --db data\overseas.db spec-dict
& $py check_xlsx.py SPEC_夏普日本.xlsx
```

补词典后：

```powershell
& $py scripts\refresh_spec.py --export-only
```

如果同一项目存在不同脚注写法，优先补基础项目名并复用归一化规则，不要为每个 `※1/※2/※3` 重复添加大量词条。

### 8.6 周度刷新返回非零

刷新脚本的非零来源：

- `spec-crawl` 无成功系列；
- `spec-export` 失败；
- Excel 不存在或损坏；
- 表头不符合格式；
- 没有型号列或规格行；
- 有未翻译项目。

查看控制台输出中的 `[FAIL]` 行。需要暂时导出排查时可使用 `--allow-incomplete`，但处理完必须补词并重新执行正式刷新。

## 9. 版本升级和回滚

### 9.1 升级前备份

Windows：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
New-Item -ItemType Directory -Force data\backup | Out-Null
Copy-Item data\overseas.db "data\backup\overseas_before_upgrade_$stamp.db"
Copy-Item SPEC_海信日本.xlsx "data\backup\SPEC_海信日本_before_upgrade_$stamp.xlsx"
Copy-Item SPEC_夏普日本.xlsx "data\backup\SPEC_夏普日本_before_upgrade_$stamp.xlsx"
```

Linux：

```bash
stamp=$(date +%Y%m%d_%H%M%S)
mkdir -p data/backup
cp data/overseas.db "data/backup/overseas_before_upgrade_${stamp}.db"
cp SPEC_海信日本.xlsx "data/backup/SPEC_海信日本_before_upgrade_${stamp}.xlsx"
cp SPEC_夏普日本.xlsx "data/backup/SPEC_夏普日本_before_upgrade_${stamp}.xlsx"
```

### 9.2 代码版本回滚

1. 停止 Windows 任务或 Linux timer；
2. 保留当前失败版本目录和日志，不要直接覆盖删除；
3. 解压上一份已验收的交付包到新的目录；
4. 复制/确认 `overseas.env`、浏览器路径和代理配置；
5. 先运行 `sites --json`；
6. 用备份数据库执行 `--export-only`，确认旧代码可以读库并导出；
7. 再决定是否恢复数据库文件。

Linux 示例：

```bash
sudo systemctl disable --now overseas-spec.timer
# 将旧包解压到新的临时目录后，先完成 sites/--export-only 验证
# 验证通过后，再切换 WorkingDirectory 或恢复旧项目目录
```

### 9.3 数据库回滚

仅当确认本周写入的数据有问题时恢复数据库：

```powershell
Copy-Item data\overseas.db data\overseas_before_restore.db
Copy-Item data\backup\overseas_before_YYYYMMDD_HHMMSS.db data\overseas.db
```

恢复后只能先执行 `--export-only` 检查，不要立即重新采集覆盖恢复点。历史周快照通常不需要删除；如果只当前周错误，也可以保留数据库后用正确代码重新采集同一 ISO 周进行 upsert 修复。

### 9.4 回滚 Excel

Excel 是可再生的交付产物。优先从正确数据库快照重新导出：

```powershell
& $py scripts\refresh_spec.py --export-only
```

只有数据库也错误时，才从 `data\backup` 恢复 Excel 文件。

## 10. 交付包使用

生成交付包：

```powershell
& $py pack.py
```

最新包命名格式：

```text
交付包/overseas-crawler_v0.3.0_YYYYMMDD_HHMMSS.zip
```

交付包包含代码、六个适配器、词典、刷新脚本、部署文件和文档；不包含 `data/`、数据库、缓存、浏览器、真实环境文件和运行生成的 Excel/CSV。

检查包：

```powershell
$zip = Get-ChildItem .\交付包\overseas-crawler_v0.3.0_*.zip | Sort-Object LastWriteTime -Descending | Select-Object -First 1
& $py -m zipfile -l $zip.FullName
```

从解压目录进行最小冒烟：

```powershell
# 解压后进入包根目录
& $py -m overseas.cli sites --json
& $py scripts\refresh_spec.py --export-only --site sharp_jp --db C:\path\to\overseas.db --output-dir C:\path\to\out
```

## 11. 合规和运行安全

- 运行前确认目标网站服务条款和内部使用授权；
- 使用合理抓取间隔，不要通过并发和极短间隔规避站点限制；

## 14. SPEC 系列状态审计（必须查看）

SPEC 不再只看 Excel 是否生成。每次 `spec-crawl` 都要区分并持久化以下三种系列级状态：

| 状态 | 判定规则 | 是否有可用 `spec_series` |
|---|---|---|
| `success` | 请求成功，解析出至少一个型号和一行规格 | 有 |
| `empty` | 请求成功，但没有可用 table、型号、JSON 或规格行；多级流程没有可用型号页也属于此类 | 通常没有 |
| `failed` | 404、其它 HTTP 错误、超时、浏览器/网络异常、解析异常；多型号系列只要有一个应抓型号未完成，也属于此类 | 可能有成功部分 |

系列状态保存在 `spec_series_status`，按 `run_id + brand + series` 唯一记录，包含请求 URL、实际 URL、尝试 URL、期望/成功/空/失败型号数、规格行数、错误类型和消息。`crawl_error` 仍保留底层 URL/入口错误；两者都不能删除或用手工空型号替代。

### 14.1 导出状态文件

```powershell
# 初始化/升级已有数据库到 schema 2（幂等）
& $py -m overseas.cli --db data\overseas.db init-db

# 导出六品牌当前每个系列的最新状态
$stamp = Get-Date -Format 'yyyyMMdd'
& $py scripts\export_spec_status.py `
    --db data\overseas.db `
    --format all `
    --out "data\SPEC_系列状态_$stamp"
```

`--format all` 生成 CSV、XLSX、JSON 三个文件；`--site` 可重复以限制品牌。状态导出和型号导出分开：`export_spec_models.py` 只输出真实型号，不会为 `empty/failed` 生成伪造型号行。

`refresh_spec.py` 正常完成每轮品牌刷新后会自动调用状态导出，文件写入其 `--output-dir`，命名为 `SPEC_系列状态_YYYYMMDD.csv/.xlsx/.json`。即使某个品牌采集或 Excel 校验失败，也会先尝试生成状态文件；定时任务仍按最终退出码告警。

### 14.2 查看状态和入口级失败

```powershell
# 最近的系列状态
& $py -c "import sqlite3; c=sqlite3.connect('data/overseas.db'); print(*c.execute('SELECT run_id,brand,series,captured_week,status,status_source,model_expected,model_ok,model_empty,model_failed,row_count,error_kind,finished_at FROM spec_series_status ORDER BY id DESC LIMIT 50'), sep='\n'); c.close()"

# 按状态统计
& $py -c "import sqlite3; c=sqlite3.connect('data/overseas.db'); print(*c.execute('SELECT captured_week,status,COUNT(*) FROM spec_series_status GROUP BY captured_week,status ORDER BY captured_week DESC,status'), sep='\n'); c.close()"

# 入口页为空或入口 HTTP/浏览器失败（入口没有具体系列行时只会出现在 crawl_error）
& $py -c "import sqlite3; c=sqlite3.connect('data/overseas.db'); print(*c.execute(\"SELECT run_id,url,stage,kind,message,created_at FROM crawl_error WHERE stage='entry' ORDER BY id DESC LIMIT 50\"), sep='\n'); c.close()"
```

入口 `list_series` 或多级 `series_entries` 返回空时，运行记录的 `crawl_run.status` 为 `failed`，并且 `crawl_error.stage=entry, kind=empty`。这种情况没有可安全命名的系列，必须同时查看入口错误，不要只看状态导出里的历史 `legacy` 成功行。

### 14.3 周度验收规则

每轮正式刷新后至少检查：

1. 状态文件中的目标系列数是否符合官网入口预期；
2. `success/empty/failed` 数量及具体系列是否有解释；
3. `success` 的 `model_ok >= 1` 且 `row_count >= 1`；
4. `empty` 和 `failed` 是否已记录 URL、错误类型/消息，并进入补采清单；
5. 多型号系列的 `model_expected = model_ok + model_empty + model_failed`，只要三者不完整就不能按 success 验收；
6. `crawl_run` 是否为 `completed`，入口为空或入口失败时必须为 `failed`；
7. Excel 的表头、型号列和中文覆盖率仍通过 `refresh_spec.py` 校验。

旧数据库在升级前没有系列状态历史时，导出脚本只把已有有效 `spec_series` 标为 `status=success, status_source=legacy`。这表示“历史上有有效数据”，不表示本周重新访问成功；空/失败的历史结果无法从旧表臆造恢复。

### 14.4 空抓取/失败补采

```powershell

```

404/网络/浏览器/解析失败先修复连通性或适配器后重试；请求成功但无 table/型号/规格行的 `empty` 不得用空规格表补齐。多型号系列即使保留成功型号，也必须按 `failed` 记录未完成计数，补齐后再产生新的 `success` 运行记录。

## 16. 価格.com 用户评价抓取（kakaku_jp）

按型号在 価格.com（kakaku.com）抓取日本电视的用户评价，**只保留指定上市年份（默认 2026）的机型**，导出为用户评价模板 Excel。当前默认针对海信（`hisense_jp`），型号清单直接来自 SPEC 型号汇总（`scripts/export_spec_models.py` 的产物）。

### 16.1 数据源与流程

每个型号依次：

1. `https://search.kakaku.com/<型号>/` 站内搜索，定位商品 `item id`（K000xxxx）。匹配优先级：文本以型号开头 > 型号作为独立词 > 子串，避免误取旧型号/配件（如搜 `50A6S` 曾误命中 2012 年的 `DCB-IP50A6SVP`）；
2. 商品页 `https://kakaku.com/item/<item>/` 读取**发售日**（`p.p-prdMakerInfo_txt` 含「発売」，如「2026年5月下旬 発売」）、**最安价格**（`p.p-prdInfoLowprice_ttl[data-jsread-lowprice]`）和**尺寸**（型号/标题里的 NN インチ）。**只有上市年份等于目标年份才继续**；
3. 优先抓 **レビュー**（结构化评价页 `review.kakaku.com/review/<item>/`，翻页抓全部）；
4. レビュー 404 或为空时，**回退抓 クチコミ**（讨论板 `bbs.kakaku.com/bbs/<item>/`）：先取讨论板列表页的主题清单，再**逐个进入讨论主题（SortID）抓全部帖与回帖**，把主题标题填入「网评标题」；最后用列表页散帖兜底。`--no-threads` 可只抓列表页不进主题。

「レビュー 404」属正常情况（该机型暂无结构化评价），会自动回退到クチコミ，不算被拦截。翻到评价尽头无内容也不算拦截；真正的拦截仍由状态码（403/429/503）、验证码关键字、正文过短三路识别捕获。

### 16.2 运行

### 16.4 翻译 / AI 三列的接入接口

第 9–11 列的翻译/AI 字段默认全空。处理逻辑集中在 `overseas/review_export.py` 的 `AiHooks`：

```python
from overseas.review_export import AiHooks
hooks = AiHooks(translate=my_translate_fn,
                extract_pros=my_pros_fn,
                extract_cons=my_cons_fn)
```

可选后端：

- **NLLB（默认）**：本地 `facebook/nllb-200-distilled-600M`，日语直译简体中文，不联网；
- **Argos**：本地日→英→中，两段离线翻译，使用 `--translate-engine argos`；
- **xinghai-ultra**：HiGPT 的 OpenAI-compatible Chat Completions。翻译、优点、缺点由三个独立选项控制：
  `--translate`、`--extract-pros`、`--extract-cons`；请求失败时回退到离线引擎（优缺点回退后留空）。

例如：

```powershell
# 只翻译
& $py scripts\crawl_kakaku_reviews.py --brand hisense_jp --year 2026 `
    --translate --translate-engine xinghai --format all

# 只提炼优点和缺点
& $py scripts\crawl_kakaku_reviews.py --brand hisense_jp --year 2026 `
    --extract-pros --extract-cons --translate-engine xinghai --format all

# 翻译、优点、缺点全部执行
& $py scripts\crawl_kakaku_reviews.py --brand hisense_jp --year 2026 `
    --translate --extract-pros --extract-cons `
    --translate-engine xinghai --format all
```

xinghai 配置只从环境变量读取，不能写入源码、Git、导出文件或日志：


`OVERSEAS_XINGHAI_SSL_VERIFY=false`，不要在公网部署中关闭证书校验。

### 16.5 每次运行的状态口径

脚本对每个型号打印并汇总以下状态：

| 状态 | 含义 |
|---|---|
| `ok` | 抓到至少一条评价 |
| `no_reviews` | 目标年份上市，但レビュー与クチコミ都为空 |
| `not_target_year` | 上市年份不是目标年份，已跳过 |
| `no_item` | 站内搜索没有匹配到该型号商品（kakaku 确实无此商品） |
| `blocked` | 被反爬拦截（可稍后重试该型号） |
| `failed` | HTTP/网络/解析异常 |

被拦截或失败的单个型号不会中断整体，末尾会列出所有非 `ok` 型号及原因，便于用 `--models` 只重试问题型号。

### 16.6 海信 2026 型号覆盖度说明

`SPEC_型号汇总` 中海信共 **44 个型号**，在 kakaku 的分布：

- **2026 上市 = 31 个**（真正需要抓评价的目标集）；
- 2025 上市 = 10 个（`not_target_year` 跳过，如 U8R/U6R 系列、116U9R）；
- kakaku 无独立商品页 = 3 个（`75A6S`、`55A6S`、`32S6S`）。

31 个 2026 型号中，只有约 10 个当前有用户评价，其余为 `no_reviews`。**这不是漏抓**：这些是 2026 年 5–8 月才上市的新机，用户评论本就很少（已核对如 43A6S 讨论板确实 0 帖）。评论数量会随时间增长，按周度重复运行即可持续补齐。


## 17. 価格.com 价格抓取与入库（价格/评论落库供后端查询）

### 17.1 价格抓取

各店铺分列价格，多品牌按品牌分块导出：

```powershell
$py = 'C:\Users\likunyuan\AppData\Local\Programs\Python\Python312\python.exe'

# 全部品牌（缺省）
& $py scripts\crawl_kakaku_prices.py

# 指定品牌 / 不按上市年份过滤
& $py scripts\crawl_kakaku_prices.py --brand hisense_jp --brand sony_jp
& $py scripts\crawl_kakaku_prices.py --year 0
```

产出 `data\价格监控_<brand>_kakaku_YYYYMMDD.csv/.xlsx`（最低价 + 8 家大型电商分列 + 溯源列）。

### 17.2 入库（--save-db）

价格与评论脚本都支持 `--save-db`，把结果写入 SQLite 供后端 API 查询（原 CSV/XLSX 仍照常产出）：

```powershell
# 价格入库：product / price_snapshot / price_shop_snapshot / kakaku_task_status
& $py scripts\crawl_kakaku_prices.py --save-db

# 评论入库：product / review（增量去重）/ kakaku_task_status
& $py scripts\crawl_kakaku_reviews.py --brand hisense_jp --year 2026 --save-db
```

落库要点：

- kakaku 机型登记为 `product`（`site=kakaku_jp`，`sku=item_id`），与 SPEC 型号可按型号对齐；
- 整体最低价写 `price_snapshot`，各店铺报价写 `price_shop_snapshot`（均为时序，只增不改）；
- 评价写 `review`，`review_key` 为 レビュー=`ReviewCD=NNN`、クチコミ=`bbs:書込番号`，
  按 `(product_id, review_key)` **增量去重**，重复运行不产生重复评价；
- 型号级状态写 `kakaku_task_status`（`ok/no_item/not_target_year/no_reviews/no_price/blocked/failed`），
  空与失败不静默，前端可展示"哪些型号没抓到、为什么"。

### 17.3 用已抓的 CSV 直接入库（免重抓，秒级）

如果价格/评论 CSV 已经抓好（当时没加 `--save-db`），不必重抓，直接导入：

```powershell
# 价格 CSV → product / price_snapshot / price_shop_snapshot / kakaku_task_status
& $py scripts\import_kakaku_files.py --prices "data\价格监控_全部品牌全部机型_kakaku_20260909.csv"

# 评论 CSV → product / review（增量去重）/ kakaku_task_status
& $py scripts\import_kakaku_files.py --reviews "data\网评汇总_hisense_kakaku_20260908.csv"

# 两者一起
& $py scripts\import_kakaku_files.py `
    --prices "data\价格监控_全部品牌全部机型_kakaku_20260909.csv" `
    --reviews "data\网评汇总_hisense_kakaku_20260908.csv"
```

说明：

- 评论 CSV 未单独存 `review_key`，导入时从「评论链接」提取：レビュー=`ReviewCD=NNN`、
  クチコミ=`bbs:SortID`，取不到用正文哈希，规则与抓取脚本一致，可与后续 `--save-db` 结果互相去重；
- 价格是时序表，导入会新增一批快照（不同采集时间），不会覆盖历史；
- 实测：一份六品牌价格 CSV（304 机型/1390 条店铺价）+ 海信评论 CSV 导入耗时秒级，
  远快于重抓（价格 30–60 分钟、评论 15–25 分钟）。

## 加拿大线（region=ca，电视 TV）

加拿大线与日本线共用同一套框架，按 `region` 区分。**只做电视**，暂不接翻译与大模型。

三条链路的数据流与日本线一致，但站点结构不同：

- **SPEC（规格）**：从 6 个品牌加拿大官网各自抓取，站点 code 与品牌 code 一致：
  `hisense_ca` / `samsung_ca` / `tcl_ca` / `lg_ca` / `sony_ca` / `philips_ca`。
- **价格 + 网评**：从多个零售站抓取，且**在同一商品页一次性同步抽取价格与评价**
  （不像日本线各访问一次）。零售站：`amazon_ca` / `bestbuy_ca` / `walmart_ca` /
  `costco_ca` / `thebrick_ca` / `leons_ca` / `visions_ca` / `canadiantire_ca`。
  默认仅 `amazon_ca` 启用，其余为强防护站（Amazon/Best Buy/Walmart/Costco/
  Canadian Tire 为 L3），联网小样本验证通过后在 `overseas/regions_config.py` 里
  把对应 `RetailSite(..., enabled=True)` 逐个打开。

### 命令行用法

```bash
# 1) 抓 SPEC（单品牌，可加 --site 限定；--series 限定系列调试）
python -m overseas.cli --db data/overseas.db spec-crawl --site hisense_ca

# 2) 周度刷新（抓 + 导出 Excel + 系列状态；--region ca 走加拿大六品牌）
python scripts/refresh_spec.py --region ca                 # 全部六品牌
python scripts/refresh_spec.py --region ca --site hisense_ca

# 3) 导出型号汇总（供价格/网评线使用；输出 data/SPEC_型号汇总_ca.csv）
python scripts/export_spec_models.py --region ca --format csv --out data/SPEC_型号汇总_ca.csv

# 4) 价格 + 网评同步抓取（读型号汇总；--sites 指定零售站；不加则用已启用的）
python scripts/crawl_ca_retail.py --region ca --brand hisense_ca --sites amazon_ca --limit-models 5 --max-reviews 10
```

输出：
- SPEC：`SPEC_<品牌>_CA.xlsx`（英文规格，不强制中文覆盖）；型号汇总 `SPEC_型号汇总_ca.csv`。
- 价格：`价格监控_加拿大_<日期>.csv/.xlsx`（一行一机型，每个零售站一列价格 + 最低价及溯源零售站）。
- 网评：`网评汇总_加拿大_<日期>.csv/.xlsx`（复用日本线 20 列模板，渠道列=零售站名）。

### 已知限制（实测 2026-09）

- **SPEC 规格深度按站不同**：LG（约 92 项）、Samsung（约 151 项）规格最全；Hisense 中等
  （约 62 项）；TCL 页面只暴露摘要规格（型号/尺寸等 4 项，完整规格在第三方组件异步加载）；
  Sony、Philips 规格为 JS 懒加载，稳定拿到的是**型号清单**（足以驱动价格/网评），完整规格为尽力而为。
- **强防护零售站**需低频，可能需加拿大住宅代理，Costco/Canadian Tire 价格可能因会员/门店墙缺失。
- **搜索匹配**：零售站按型号搜索的相关性有限，`find_product` 只在候选标题/型号确实包含该型号时
  才判为命中（宁缺毋滥），避免把配件/无关商品误当成匹配。
- 价格/网评当前只导出文件，不落库（与日本线 AI 三列不入库现状一致）。

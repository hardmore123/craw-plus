# 价格 vs 网评覆盖差异分析报告

> 2026-09-26 | 回答用户问题："价格和网评不都是抓取自同一个网站吗，为什么可抓取的网站数量不同"

## 一、核心结论

**价格和网评确实抓取自同一个网站的同一个 PDP（商品详情页），但能抓到价格 ≠ 能抓到网评。**

差异根因不是"去了不同的网站"，而是：**同一 PDP 页面上，价格几乎总是存在（HTML/JSON-LD），但网评的存在形式千差万别，很多站需要第三方评价系统的 API 逆向才能抓到，不是简单解析 HTML 就行。**

## 三、84站"有价格但无网评"的根因分类

对 84 个"有价格但无网评"的站逐一 PDP 探测，分为 5 类：

### 类1: JSON-LD reviews 可抓但 spec 未配（6站 → 已修复 ✅）

这些站的 PDP 实际有 JSON-LD `review` 数组，只是 spec 中 `reviews.source` 配成了 `"none"`。

| 站点 | 新增网评数 | reviews.source |
|------|-----------|----------------|
| alternate_de | 1 | jsonld |
| komplett_se | 3 | jsonld |
| morele_pl | 14 | jsonld |
| thebrick_ca | 1 | jsonld（已有401条，再补1条） |
| vandenborre_be | 5 | jsonld |
| verkkokauppa_fi | 4 | jsonld |

**处置**：更新 spec 添加 `reviews.source=jsonld` + capabilities 加 `reviews` + 抓取网评入库。

### 类2: 第三方评价系统需 API 逆向（15站，暂不抓）

PDP 有评价区但由第三方 JS 动态渲染，HTML 中无 JSON-LD review 数组，需 API 逆向。

| 评价系统 | 站点 |
|----------|------|
| BazaarVoice | mediamarkt_be/ch/it/nl, lg_ec, olimpica_co, tcl_cl, topocentras_lt |
| Yotpo | japon_ec |
| Feefo | — |
| 自研API | ananas_rs, eprice_it, estilos_pe, leclerc_fr, metro_pe, plaisio_gr |

**处置**：记录在案，需后续逐站 API 逆向（参考已有经验: mediamarkt_pl 用 JSON-LD、exito_co 用 VTEX GraphQL、elektra_gt 用 Yotpo API）。

### 类3: 仅 aggregateRating 无 review 正文（8站，留空不造假）

PDP 有 JSON-LD `aggregateRating`（评分+总数）但没有 `review` 数组（无评价正文）。

| 站点 | 现状 |
|------|------|
| coolblue_be/nl, hepsiburada_tr, kakaku_jp, power_dk/no/se, rueducommerce_fr | 只有评分汇总，无明细 |

**处置**：按"缺价 > 错价"红线，无评价正文不造假，`reviews.source=none` 正确。

### 类4: 确实无任何评价（49站，正确）

PDP 页面完全没有评价区，`reviews.source=none` 配置正确。

| 代表站 | 说明 |
|--------|------|
| amazon_be/nl/se/tr | 亚马逊地区站用 DOM `[data-hook='review']` 非 JSON-LD，探测判 none 正确 |
| auchan_fr, carsa_pe, digitec_ch, cresa_ec, marcimex_ec 等 | 站点本身无评价功能或评价区为空 |

### 类5: WAF 拦截无法探测（4站，需住宅 IP）

| 站点 | 拦截 |
|------|------|
| mediaexpert_pl, mimovrste_si, pigu_lt, tehnomanija_rs | 403/超时 |

**处置**：保持 `reviews.source=none`，需住宅 IP 复测。

## 四、为什么价格比网评容易抓？

| 维度 | 价格 | 网评 |
|------|------|------|
| **存在形式** | 几乎所有 PDP 都有价格（HTML/JSON-LD/meta） | 很多站用第三方评价系统（BV/Yotpo/Feefo）动态加载 |
| **提取方式** | CSS 选择器 / JSON-LD `offers.price` 直接取 | 需要解析 review 数组或调用第三方 API |
| **JS 渲染** | 价格通常在初始 HTML 中 | 评价常由 JS hydration 后才出现 |
| **反爬** | PDP 可达即可 | 评价 API 可能有独立反爬（BV private key、Yotpo app_key） |
| **数据结构** | 单值（一个数字+货币） | 多值数组（每条含 author/rating/body/date，结构各异） |

**一句话总结**：价格是"一个数字"，网评是"一个动态加载的第三方组件"——后者天然更难。

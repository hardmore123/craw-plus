## 五、对爬取项目的建议

1. **必须走代理**:直连时 `bestbuy.com/.ca`、`walmart.com/.ca/.com.mx`、`costco.com/.ca`、`visions.ca`、`canadiantire.ca`、`liverpool.com.mx`、`coppel.com` 等因 SNI 阻断无法建立 TLS;这是链路问题,与站点反爬无关。
2. **客户端必须伪装成浏览器 TLS 指纹并协商 HTTP/2**。实测关键证据:同一个出口 IP 下,仅支持 HTTP/1.1 且无 ALPN 的客户端访问 `bestbuy.com`、`coppel.com`、`canadiantire.ca` 会被服务器在 TLS 握手完成后立刻 `ECONNRESET`;改为协商 `ALPN=h2` 后同样请求全部返回 200 真实页面。Python 的 `requests`/`httpx` 默认指纹会被同样拦截,建议使用 `curl_cffi`(impersonate)或 `httpx` + HTTP/2。
3. **当前 Clash 节点是机房 IP(Contabo / US),会持续触发风控**。`Amazon`(AWS WAF 挑战)、`Visions`、`Palacio`(Cloudflare)、`BestBuy CA`(403 Access Denied)、`Sams MX` / `Walmart MX`(身份验证)均属此类。换成住宅 IP 节点(Residential)通常可直接通过;或在采集时接入打码/指纹浏览器。
4. **部分结果是波动的**:`Palacio` 在两次测试间分别返回 Cloudflare 403 和 200 真实页面;`BestBuy CA` 分别为 403 与连接重置。采集端需要实现重试 + 失败降级。
5. **对强风控站点建议上无头浏览器**:`Amazon`、`Visions`、`Sams MX`、`Walmart MX` 返回的是需要执行 JS 才能通过的挑战页(202/2KB 或 Cloudflare "Just a moment..."),用 Playwright/Puppeteer 走真实浏览器内核是最稳的方案。

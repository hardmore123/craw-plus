### walmart_us 复测（2026-09-20，出口已是美国 IP）

> 复测前提：本机出口经 `ipinfo.io` 确认为 **美国 IP**（170.178.173.10 / Los Angeles /
> AS46844 Sharktech），即"当前没有美国线路"这一旧结论已不成立。结论仍为**不可抓**，
> 但原因变了：**不是没有线路，而是线路类型不对**。

| 探测方式 | 结果 |
|---|---|
| 首页 `https://www.walmart.com/`（HTTP 直连） | 200，345 KB，含 `__NEXT_DATA__` + 2 个 JSON-LD 块 → **正常页面** |
| 搜索页 `https://www.walmart.com/search?q=Hisense+tv`（HTTP 直连） | 200，15 KB，命中 `robot or human` + `px-captcha` → **PerimeterX 验证页** |
| 搜索页（**真实浏览器** Playwright/Edge，`diag_retail_search.py`） | `ok=False status=200 blocked=True reason=marker:robot or human`，17 KB，候选容器命中数 **0** → **仍被拦** |

**结论**：真实浏览器 + 当前美国出口 IP 依然拿不到 Walmart 搜索候选。Sharktech 是
**机房 IP**，PerimeterX 对其风险评分高；首页能开不代表搜索/商品页能抓。因此：

- `regions_config` 中 `walmart_us` 必须保持 `enabled=False`（本次已从误置的 `True` 改回）。
- 需要的是**美国住宅/移动代理**，而非任意美国出口。
- 反爬识别工作正常：`BlockDetector` 内置 `robot or human` 已命中并返回 `blocked`，
  站级熔断（连续 5 个型号）会正常触发 → 不会出现"被拦却静默记成 no_item"或死循环。

**待校准项（有住宅代理后再做）**：Walmart 正常搜索/PDP 页是否在**前 8000 字符内**
带 PerimeterX bootstrap 字样。已实测：首页完整 HTML 里确含 `perimeterx`/`captcha`，
但**不在前 8000 字符内**，而 `BlockDetector` 只扫 `title + html[:8000]`，故首页不误报；
拦截页则把 `robot or human` 放在窗口内，能被稳定识别。**即当前无需 `block_marker_allowlist`。**
仅当正常 search/PDP 页在窗口内出现 PX 字样时才需复议，且前提是拦截页仍能被
`robot or human` 单点识别（漏报会把整站型号静默记成 `no_item`，比误报 blocked 危害更大）。

#### 逐路由复测（2026-09-20 续）：**"可访问"的只有营销壳，数据路由全拦**

上一节"首页 200"容易被误读成"站点可抓"，故补做路由级探测（HTTP 直连 + 真实浏览器）。

| 路由 | HTTP 直连结果 | 判定 |
|---|---|---|
| `/robots.txt` | 200 / 3.5 KB | ✅ 干净 |
| `/`（首页） | 200 / 345 KB / 含 `__NEXT_DATA__` + 2 个 JSON-LD | ✅ 干净（**但无商品数据**，见下） |
| `/search?q=Hisense+tv` | 200 / **15,190 B** | ❌ PerimeterX 验证页 |
| `/browse/electronics/televisions/…` | 200 / **15,190 B** | ❌ 同一个验证页 |
| `/ip/18060066783`（短链） | 200 / **15,190 B** | ❌ 同一个验证页 |
| `/ip/<slug>/18060066783`（带 slug） | 200 / **15,190 B** | ❌ 同一个验证页 |
| `/ip/<slug>/16104452413`（另一型号） | 200 / **15,190 B** | ❌ 同一个验证页 |
| 真实浏览器：首页 | `ok=True blocked=False` / 370 KB | ✅ 干净 |
| 真实浏览器：首页→搜索（同 context 带 cookie） | `blocked=True reason=marker:robot or human` / 16,963 B | ❌ 过首页**不能**解锁 |
| 真实浏览器：首页→PDP（同 context） | `blocked=True reason=marker:robot or human` / 16,963 B | ❌ 同样被拦 |

**所有数据路由返回的都是同一个 15,190 字节的验证页**（搜索/类目/三个不同 PDP 长度逐字节相同），
说明这是**边缘按路由统一下发的 interstitial**，不是按 URL 或按 IP 的偶发拦截。

**为什么首页能开**：PerimeterX 是**按路由 + 风险评分**下发的，站点根路径（首页、robots）
必须对搜索引擎和每一个首次落地的人类开放，故不挑战；而搜索/类目/商品页是数据库支撑、
且是最容易被批量抓取的路由，故一律挑战。**"域名能应答"与"能拿到价格+网评"是两件事。**

**首页那 345 KB 实际是什么**（实测内容分析）：

| 指标 | 值 |
|---|---|
| `<title>` | `Walmart \| Save Money. Live better.` |
| `__NEXT_DATA__` 块长度 | **989 字节**（近乎空壳，无目录数据） |
| 全页 `/ip/` 出现次数 | **1** |
| `Hisense` 出现次数 | **0** |
| `add to cart` 出现次数 | 0 |
| "价格形态" `$x.xx` 命中 3 处 | 实为**购物车合计 `$0.00`** 与促销横幅 `Lunch gear from $2.97`，**非商品价** |

即：可访问的部分**零可用数据**——既没有商品链接（捞不到 itemId 绕开搜索），
也没有价格/评价。因此"首页可访问"对价格+网评抓取**不构成任何可行路径**。

**旧记录为何是"200 OK"**：项目早期连通性核查只验证了域名/首页能应答（浅层检查），
未触及数据路由——这正是它误导的来源，也是 `walmart_us.retail.json` 至今只能是
`candidate` 的原因。**结论：`walmart_us` 保持 `enabled=False`；需要美国住宅/移动代理。**

## 三、Shopify 站 captcha 误判修复（leons_ca/thebrick_ca）

leons_ca/thebrick_ca 是 Shopify 站，正常页面内嵌 `captcha-bootstrap` 脚本，
BlockDetector 误判拦截。修复：adapter 加 `block_marker_allowlist=("captcha",)` +
`crawl_ca_retail._make_fetcher` 读 allowlist。修复后两站都实测通过。

## 四、防死循环机制（已落地）

每个（型号 × 站点）任务的终止条件（任一命中即停，不重试）：
1. 累计评价数 ≥ 100 → status=ok（达上限）
2. 本页无新评价 → status=ok（增量到底）
3. 翻页数 ≥ max_pages（10）→ status=ok（安全阀）
4. res.blocked/captcha → status=blocked，记 block_reason，跳过该站
5. HTTP 403/404/5xx 连续 2 次 → status=failed，跳过该型号
6. 单站连续 5 个 blocked/410/403/429 → 站级熔断，跳过该站剩余型号

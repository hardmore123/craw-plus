# 北美 18 个零售站：反爬拦截分类与代理需求判定（定版）

> 日期：2026-09-20
> 方法：**真实浏览器**（Playwright/Edge）逐个站访问搜索路由；判定口径用站点自己的
> `BlockDetector`（含 `block_marker_allowlist` 豁免），与生产抓取完全一致。
> 对照跑了一轮纯 HTTP 探测，用来暴露"HTTP 被拦 ≠ 浏览器被拦"的差异。
> 工具：`scripts/probe_na_retail_access.py`（自检：`--selftest`）

---

## 0. 一句话结论

**18 站里有 7 站真正需要住宅/移动代理**，其余 11 站从**美国机房 IP** 直连就能抓
（其中 2 站另有配置问题，与代理无关）。

| 分组 | 站数 | 站点 |
|---|---|---|
| ✅ **不需要代理**（正常可抓） | 9 | `amazon_ca` `amazon_us` `amazon_mx` `costco_ca` `thebrick_ca` `leons_ca` `canadiantire_ca` `liverpool_mx` `palacio_mx` |
| ⚙️ **不是代理问题**（配置） | 2 | `costco_us`（scroll 已修）`bestbuy_us`（allowlist 已补；另缺 `supports_retail`） |
| ❌ **需要住宅/移动代理** | 7 | `walmart_us` `walmart_ca` `walmart_mx` `sams_mx` `bestbuy_ca` `visions_ca` `coppel_mx` |

> **`sams_mx` 归类的更正（2026-09-20 追加实测）**：本节初稿把它判为"不是代理问题，
> 只是搜索 URL 写错（404）"。逐候选路径复测后证明**这个判断是错的**：
> `/busca?query=`（适配器原用）确实是无效路由（404），但 `/search?q=` **被站点识别**
> （转入 PerimeterX 挑战而非 404），且**首页也返回 `<title>Verify Your Identity</title>`**
> —— 即**整站在 PerimeterX 之后**，与 `walmart_mx` 同族。
> 所以 `sams_mx` 同时有两个问题：**适配器 URL 写错** + **站点被 PX 拦**。

## 1. 实验条件（决定结论边界）

| 项 | 实测值 |
|---|---|
| 直连出口 IP | **美国机房 IP**，Sharktech AS46844 / Los Angeles；IP 在池内轮换（观测到 `170.178.173.10` / `45.58.161.90`） |
| 本地代理 `127.0.0.1:7877` | **与直连是同一条线路**（出口 IP 相同）→ 无备选线路 |
| 会话中线路状态 | 中途代理客户端退出 + Windows 系统代理残留（`ProxyEnable=1` → `127.0.0.1:7877`），导致全部出网失败；重连后恢复 |

判定口径：

- **美国站**：地理正确、**类型不对** → 被真拦即"住宅/移动代理问题"。
- **加拿大/墨西哥站**：地理+类型都不对。但归因可推断：既然多个加/墨站在美国 IP 下
  完全正常，说明这些国家的站点**普遍不做地理封锁**，其余站被拦更可能是**机房 IP 信誉**。

> ⚠️ 边界：这是**推断**而非证明。要 100% 分离"地理"与"类型"，需一条加/墨住宅线路。

## 3. 7 个需代理的站：拦截形态与归因

| 站点 | 拦截形态 | 归因 | 依据 |
|---|---|---|---|
| `walmart_us` | PerimeterX 人机挑战（`<title>` 即 `Robot or human?`） | **IP 类型**（地理已正确） | 我们就是美国 IP，仍被挑战 |
| `walmart_ca` | PerimeterX `Verify Your Identity` | **IP 类型** | 5 个其他加拿大站在美国 IP 下完全正常 → 加站不 geo-block |
| `walmart_mx` | PerimeterX `Verifica tu identidad` | **IP 类型** | `liverpool_mx`/`palacio_mx`/`amazon_mx` 在美国 IP 下正常 |
| `sams_mx` | PerimeterX `Verify Your Identity`（**首页亦然** → 整站被挡） | **IP 类型** | 同 `walmart_mx`（sams.com.mx 属 Walmart 系）；且 `/search` 被识别而非 404 |
| `bestbuy_ca` | 403 / **305 B** 极小响应 `Access Denied` | **IP 信誉（机房段）** | 典型 CDN/WAF 机房段拒绝页 |
| `visions_ca` | 403 / Cloudflare 挑战页 | **IP 信誉** | 同上 |
| `coppel_mx` | 403 / **307 B** 极小响应 `Access Denied` | **IP 信誉** | 同上 |

**共性**：要么是 PerimeterX 人机挑战，要么是机房段 403 —— 都按 **IP 信誉评分**拒绝，
而非按国家拒绝。**换住宅/移动出口是最直接的解法。**

**旁证**：池内两个不同 IP（`170.178.173.10` / `45.58.161.90`）拦截行为一致
→ 被拒的是**整个机房 ASN 段**，不是某个被拉黑的 IP。**单纯换机房 IP 无效。**

## 4. 三处必须纠正的历史误判（本轮最大价值）

旧结论大多是"用纯 HTTP 或只看 marker 命中"得出的，**错的比对的多**：

| 站点 | 旧结论 | 真相 | 根因 |
|---|---|---|---|
| `thebrick_ca` / `leons_ca` / `costco_ca` / `costco_us` | "被 captcha 拦" | **正常**（前两站 09-20 已实抓 761 / 327 条价格） | 正常页内嵌 `captcha` 字样；站点已声明 `block_marker_allowlist=("captcha",)`，**HTTP 探测脚本没读这个豁免** |
| `amazon_ca/us/mx` | "202/503 被拦" | **正常**（浏览器 1.5–2.3 MB 真实结果，23–30 候选） | 站 `requires_browser=True`，纯 urllib 被 TLS 指纹/请求头特征拦 |
| `canadiantire_ca` / `palacio_mx` / `costco_us` | "403 / 被拦" | **正常**（浏览器 0.5–4.0 MB 真实页） | 同上 |

### 4.1 两个**新发现**的误报（此前未记录）

| 站点 | 表面现象 | 实际原因 |
|---|---|---|
| `sams_mx` | `404` + 命中 `captcha` → 曾被记为"404+captcha 被拦" | `captcha` 命中处上下文是 **CSP 声明**：`... www.recaptcha.net; img-src * ...`。**不是验证页**。真实问题是搜索 **404**（内容里出现 `walmart.com.mx`，疑似跳转链路断了） |
| `bestbuy_us` | `blocked=True` | 1.86 MB **真实搜索结果页**（标题 `Samsung tv - Best Buy`、412 个 `/site/` 链接、37 处 Add to Cart、**0** 个验证码 iframe）。触发 blocked 的 `captcha` 是 `<script src=".../recaptcha__en.js">`（表单用） → **需补 allowlist** |

### 4.2 `bestbuy_us` 是混合情况

`_BLOCK_MARKERS` 里有一条专为它加的 `"best buy international"`（注释写明：Best Buy 美国站
对非美国出口 IP **不是 403，而是 200 + 国际选择页**）。实测：

| 路由 | 结果 | 判定 |
|---|---|---|
| 首页 | 200 / 7,694 B / `<title>Best Buy International: Select your Country</title>` | ✅ **正确拦截**（边缘把本机房 IP 判为**境外**） |
| 搜索 | 200 / 1,865,694 B / 真实结果 | ❌ **误报**（`recaptcha__en.js` 触发 `captcha`） |

即搜索页能出真实结果，但首页说明边缘把该机房 IP 当境外 → 不宜与 `walmart_*` 硬拦截同等
对待，**建议小样本试抓并观察 PDP 是否被跳转**。

> **标记缺口**：Best Buy 的 Akamai 挑战页文案是 `Pardon Our Interruption`，而
> `_BLOCK_MARKERS` 里**没有**这条 → 若改用 Akamai 挑战会**漏判**。建议补进标记表。

## 5. 方法论红线（都踩过，别再犯）

1. **不要只用纯 HTTP 探测给站点定性。** 本轮 18 站里有 **9 站**在 HTTP 下表现为
   "被拦"而浏览器下正常（`amazon_ca/us/mx`、`canadiantire_ca`、`palacio_mx`、
   `thebrick_ca`、`leons_ca`、`costco_ca`、`costco_us`）。
   定性必须走浏览器 + 站点自己的 `BlockDetector`（含 allowlist）。
2. **不要只看 marker 命中。** `captcha` 在正常页里出现得极频繁（CSP 声明、reCAPTCHA
   脚本、Cloudflare 引导）。必须看**命中偏移、上下文、页面体积与业务内容**交叉判断。
3. **HTTP 404 优先于 blocked**（项目红线）。`sams_mx` 就是被这条错记成"被拦"的。
4. **并发会制造假拦截。** `workers=2` + 大滚动时，`amazon_us`/`bestbuy_us` 出现过
   `len=0 / no_anchor_element`；`workers=1` 复测全部正常。工具已加**空页重试**。
5. **站点会间歇。** `palacio_mx` 有一轮命中 Cloudflare 403、其余轮次正常。
   **单轮探测不足以定论**，关键站点要跑 2–3 轮。
6. **★ 加 `block_marker_allowlist` 之前，先确认"真实拦截仍能被别的标记抓到"。**
   本轮亲自踩到：给 `sams_mx` 加 `("captcha",)` 后，它的 PerimeterX 挑战页
   （标记是 `px-captcha`，**`captcha` 是它的子串**）被一起豁免，
   `BlockDetector` 从 `blocked=True` 变成 `blocked=False` → 真实拦截被"消音"，
   下一步就会被记成 `no_item`（静默丢数据）。
   **修法不是简单回退豁免，而是补齐更具体的标记**：已给 `_BLOCK_MARKERS` 增加
   PerimeterX 标题类标记 `verify your identity` / `verifica tu identidad`，
   之后"豁免 `captcha`"才是安全的（已用三种场景离线验证）：
   - PX 挑战页 + 豁免 `captcha` → 仍判 `blocked`（靠标题标记）✓
   - Shopify 正常页 + 豁免 `captcha` → 不误报 ✓

## 7. 复现方式

```powershell
# 全量 18 站（浏览器口径，与生产一致）——workers=1 最稳，2 以上需靠空页重试兜底
py -3.12 scripts/probe_na_retail_access.py --regions ca us mx --phase browser --workers 1 --scroll 12 --wait-ms 12000

# 同时跑 HTTP 对照，暴露"HTTP 被拦 ≠ 浏览器被拦"的差异
py -3.12 scripts/probe_na_retail_access.py --regions ca us mx --phase both --workers 1

# 只测某几个站
py -3.12 scripts/probe_na_retail_access.py --sites walmart_us bestbuy_us --phase browser

# 离线自检判据（不联网，6 个用例）
py -3.12 scripts/probe_na_retail_access.py --selftest
```

工具的判据顺序（每条都是本轮踩出来的，`--selftest` 把它们固化成用例）：

| # | 判据 | 来源 |
|---|---|---|
| 1 | 网络错误 → `TIMEOUT`/`ERROR` | — |
| 2 | 判定用**站点自己的 `BlockDetector`**（含 `block_marker_allowlist` 豁免） | `thebrick_ca`/`leons_ca`/`costco_*` 被 HTTP 探测误判 |
| 3 | **HTTP 404/410 优先于 blocked** | 项目红线；`sams_mx` 被记成"404+captcha 被拦" |
| 4 | **明确挑战标记**（`robot or human` / `verify your identity` / `just a moment` / `access denied`…）命中即判 `BLOCKED`，不受上下文与体积影响 | `walmart_ca`：早期版本被歧义标记的上下文放过了 |
| 5 | **歧义标记**（`captcha`/`perimeterx`/`px-captcha`）才走上下文推断：命中处是**脚本/CSP 引用**或页面**体积大且业务内容充足** → `SUSPECT_FALSE_POSITIVE` | `sams_mx` 的 CSP `www.recaptcha.net`；`bestbuy_us` 的 `recaptcha__en.js` |
| 6 | **站点自己的解析器 0 候选** → `OK_NO_CONTENT`（不是 `OK`） | `costco_us`：2.96 MB 真页但需更大 scroll |

同时输出 marker 的**命中偏移 + 上下文片段 + 是否在前 8000 字符内**（即
`BlockDetector` 的扫描窗口），便于人工复核。

结果：`data/_smoke/na_access_probe.json`。

> 注：判定依赖**当前出口 IP 的类型**。本次出口为美国机房 IP（Sharktech，池内轮换），
> 换线路后结论会变，需重跑。

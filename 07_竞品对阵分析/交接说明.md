# 竞品对阵分析 · 交接说明

## 1. 这是什么
把海信机型和各国竞品，按**同一套标准规格参数**做对比，出规格对比表、雷达图和 AI 对阵结论（TCP 报告）。
数据全部来自主库 `data/overseas.db`（零售价格、评价、官网 SPEC），不单独爬取。

## 2. 本文件夹内容
> 本目录是**代码副本**，方便单独交接查阅。实际运行用主包 `../01_项目代码/`（它是同一个 Python 包，
> 自带主库和依赖）。本目录的 `overseas/...` 不能脱离主包单独 `python` 运行，缺 `overseas/db.py`、`config.py` 等基础模块。

| 路径 | 作用 |
|---|---|
| `run_benchmark_server.py` | 启动 Web 服务（端口 8090）。等价于 `python -m overseas.benchmark_server` |
| `启动竞品对阵分析.bat` | Windows 双击启动（内部调上面脚本；AI 代理说明也在里面） |
| `overseas/benchmark_server.py` | 服务主体 + 全部 `/api/*` 路由（HTTP，标准库实现） |
| `overseas/benchmark_static/index.html` + `echarts.min.js` | 前端页面（纯静态，ECharts 画雷达/柱状） |
| `maintain_benchmark_tables.py` | 维护脚本：从 `spec_row`/`product_spec` 按映射规则重算 `dim_*`/`fact_*` 表 |
| `overseas/backfill.py` | 规格回溯补全：缺某参数时去官网/库里补 |
| `overseas/report/generate_tcp_report.py` | 命令行出单机型 TCP 对标报告（6-Agent 协作） |
| `overseas/report/generate_report.py` | 通用报告框架（TCP 报告复用它） |
| `scripts/import_benchmark_tables.py` | 从旧库导入 dim/fact 表（已执行过，交接后一般不用） |
| `scripts/import_missing_models.py` / `expand_mapping_and_match.py` / `check_tcl_no_jpy.py` / `fix_jp_ultimate.py` | 一次性数据修补工具 |
| `样例_竞品对阵分析_日本线65寸旗舰.html` / `.json` | 一份已生成的对阵结果，看成品长什么样 |

## 3. 用到的数据库表（主库 `data/overseas.db`）
| 表 | 用途 |
|---|---|
| dim_product_model | 归一化机型（品牌/型号/尺寸/区域/价位/是否海信 our_brand=1） |
| dim_spec_parameter | 18 个标准对比参数（峰值亮度、刷新率、HDR、分区数…，含单位、是否越大越好、雷达维度） |
| dim_spec_item_map | 源术语→标准参数的映射规则（status=CONFIRMED 才是人工确认过的） |
| dim_spec_normalization_map | 跨品牌同义词分组 |
| fact_spec_value | 机型×参数取值（value_text 原文 + value_numeric 数值 + confidence） |
| fact_benchmark_comparison | 对阵结论（我方 vs 竞品，优势/劣势/机会点 JSON） |
| product / price_snapshot / review / media_review | 价格、评价、媒体评测（供页面展示与 AI 引用） |
| spec_row / product_spec | 原始规格来源（映射的输入） |

逐列说明见 `../01_项目代码/docs/数据库结构说明.md` §3.5 与 `数据库表结构明细.md`。

## 4. 启动与使用
```powershell
cd ..\01_项目代码
py -3.12 -m pip install -r requirements.txt      # 首次
py -3.12 run_benchmark_server.py                 # 启动，浏览器开 http://127.0.0.1:8090
```
- `/api/*` 接口：`health`（健康 + AI 是否就绪）、`countries`、`sizes`、`models`、`spec`、`radar`、
  `ai-analysis`、`ai-recommend`、`auto-trace`、`backfill` / `backfill-crawl` / `backfill-status`。
- 规格对比、雷达图**开箱即用**，只读主库。
- AI 对阵解读依赖本机的 xinghai 转换代理 `http://127.0.0.1:8082/v1`（`/api/health` 的 `ai_ready` 反映是否可用）；
  没有该代理时页面能看，AI 按钮不可用。
- 原始数据更新后，规格对比不会自动变：要重跑 `py -3.12 maintain_benchmark_tables.py` 重算 dim/fact。

单机型 TCP 报告（命令行）：
```powershell
cd ..\01_项目代码
python -m overseas.report.generate_tcp_report --hisense 55U7SG --competitor UN55U8000HFXZC --output report.md
```
报告的业务参照（成品 PPT、邮件、模板结构、已生成报告）在 `../06_文档/TCP报告参考模板/`。

## 5. 完成度
- 服务可启动、三类只读接口（health/countries/sizes 等）实测 200；规格对比与雷达图可用。
- `fact_spec_value` 已有 52,636 条（18 个参数，RESOLUTION/HDMI/WIFI/HDR 等覆盖最全，PEAK_BRIGHTNESS 等高级参数覆盖较少）。
- `fact_benchmark_comparison` 只有 4 条示例对阵结论——**对阵结论本身还没批量生成**。

## 6. 待完善 / 已知问题
1. `fact_*` 是加工产物，主库更新后不自动刷新，需手动跑 `maintain_benchmark_tables.py`；建议接到全量抓取流程之后。
2. `dim_product_model` 有脏数据：5,133 行 region 为空，存在 `AMAZON 2DA`、`GENERICO 8CM`、型号 `40` 这类从标题误切的机型；
   对阵时只用 `our_brand=1` 的海信机型 + 有 size_inch、有足够 fact_spec_value 的竞品。
3. `dim_spec_item_map` 里 `AUTO` 状态的映射未经人工确认，可能把「HDMI 数量」配成「HDMI 版本」之类，用前抽查。
4. AI 功能绑定内网 xinghai 代理，换环境要改 `/api/health` 读到的 `ai_base`（在 `benchmark_server.py`）。
5. 服务无鉴权、只监听本机；对外开放需自行加访问控制与反代。
